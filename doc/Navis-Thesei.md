# Navis-Thesei: 文档治理形式化理论（归档 · Ref 层）

> **命名**: Navis (船) + Theseus (忒修斯) — 忒修斯之船悖论用于文档治理: 文档如船, 每条信息是木板, 项目演进时木板该如何换。
> **本文件定位 (据自身 P4 归档约定)**: 元方法论, 非日常承重文档。定义 HANDOFF/doc 体系的治理规则与命名约定, 需查时来, 不占主阅读流。
> **理论提出/实证**: 2026-08-20, 基于 NovaLibreOfficePlayer HANDOFF.md 治理实践 + 攻击测试实证。

---

## 1. 核心判据

木板（文档中每条信息）留存的理由是**它在承重**, 不是它曾经在那里。

- `L(b)` 承重: 当前情境仍引用此木板
- `Red(b)` 冗余: 另一木板完全覆盖其信息
- `Stale(b)` 过期: 历史承重, 当前不承重
- `Miss(d)` 缺失: 某读者需求无木板满足（作用于需求, 非木板）

---

## 2. 治理原则（落地核心）

| 原则 | 含义 |
|---|---|
| **P1 留存** | `L(b) ∧ ¬Red(b)` — 承重且非冗余才留 |
| **P2 清理** | `Red(b) ∨ Stale(b)` — 冗余或过期则清 |
| **P3 补充** | `Miss(d)` — 存在未满足需求则新建 |
| **P4 归档** | `Stale(b) → 归档(非删除)` — 保留可追溯, 不占主流程 |
| **P5 活性** | 情境变化时定期重评估 `S_c`, 重新分类 |

**关键洞察**: 抑制熵增不是少写, 而是定期清理 + 分层 + 明确失效条件。少写≠低熵（增 Miss）, 不清理=熵增（Stale/Red 积累）, 只清理不补充=熵增（文档失指导价值）。

---

## 3. 失效条件（最有工程价值的概念）

每块承重木板应标注失效条件 `failure(b)`: 使 `L(b) → ¬L(b)` 的情境变化。

```
b = "Xvfb 恒无 GPU, 软件渲染定论"
failure(b) = {s | s.tech = Wayland ∨ s.tech = GPU-accelerated-Xvfb}
```

失效条件对应 HANDOFF 二章经验表的"失效条件表"——告知维护者: 情境触及失效条件时需重估此木板。

---

## 4. 分层管理

| 层 | 定义 | 阅读顺序 |
|---|---|---|
| **Core** | `L(b) ∧ high_confidence` — 永久承重(源码级/多次实测) | 先读 |
| **Aux** | `L(b) ∧ medium_confidence` — 当前承重, 可能随情境变 | 按需读 |
| **Ref** | `Red(b) ∨ Stale(b)` — 归档, 可追溯不占主流程 | 必要时查（本文件即此层） |

---

## 5. 归档命名约定（P4 实施, 本项目已采用）

```
归档文件: <name>.<YYYYMMDD>.achieved.<ext>      (如 attack-report.20260820.achieved.md)
归档段落: 章节标题加 " — 已闭环 (YYYY-MM-DD)"     (如 HANDOFF 3.0)
```

## 6. 实证修正（2026-08-20 攻击测试后）

原理论 3 处不严谨, 修正如下:

- **PartialRed（修正 Red 判定）**: 实践中罕见"完全覆盖", 常见"部分覆盖" — `b'` 覆盖 `b` 的部分情境但不全部。PartialRed 木板**不能直接清理**（仍有独有承重）, 仅标记"可部分合并"。**实证**: HANDOFF 七章 V1（Destroy 与帧泵竞态）与经验 42（FramePump 契约）是 PartialRed — 经验 42 覆盖"泵必须先 Stop"契约, 但未覆盖"Stop 与 UpdateFrame 交错的窗口期"盲区。→ **这是 V1 与经验 42 不合并的护栏, 熵减时勿误并**。
- **StaleInstance（修正 Stale 判定）**: 需区分"经验本身"（如经验 43 BootLock 死锁根因, 仍被代码引用→L）与"经验的应用实例"（如 Create 竞态探针, 修复后不可复现→Stale 实例）。Stale 可作用于应用实例, 而非仅木板本身。
- **归档命名（修正 P4 实施）**: 见第 5 节。

**理论有效性**: 四分类 + PartialRed + StaleInstance 能对全部漏洞明确分类, 指导了"1 条经验留存(45) + 3 条已知漏洞(V1/V2/V3) + 1 个探针归档删除"的治理动作。局限性（R(b,s) 人工判定、S 不可穷举）在实证中确认。
